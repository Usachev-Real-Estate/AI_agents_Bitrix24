# Черновик v3: критерий «заполнено информативно и верно»

**Статус: правила согласованы 2026-08-20 (v3), в разработке.**
Ничего пока не в коде.

## Зачем

Сегодня у агента одна ступенька: `recoverable` — «хоть что-то можно понять».
Между пустой карточкой и образцовой различия нет. Пилот на 20 сделках это
подтвердил: 8 покупателей получили `recoverable=true` без бюджета и сроков.

Нужна положительная оценка, а не только отсутствие претензий.

## Что изменилось в этой итерации

* «Задаток», «Сделка», «Переговоры» — **не в контроле качества**, их ведёт руководство.
* «Агент» — не задача LLM: **прямая проверка** типа контакта.
* «Мотивация продажи» на «Назначении встречи» — убрана.
* На «Подготовке в рекламу» цена обязательна, фотосессия и документы —
  **условные**: если факт назван, он засчитывается, но за отсутствие не наказываем
  (за отсутствие уже отвечает основной аудит).
* Порог «терпимо» — теперь про **сходство комментария с разговором + заполненность полей**,
  а не «один недостающий факт».
* Расхождения делятся на **мелкие** (даты, суммы близки) и **существенные**
  (искажена позиция или готовность клиента).

## Как считается

Модель по-прежнему **только извлекает факты с цитатами** и рубрики не видит.
Полнота считается кодом — сколько обязательных для этапа фактов найдено.

## Что делает LLM, а что — прямая проверка CRM

Один агент на всё — плохая архитектура. Разделяем:

| Задача | Кто делает |
|---|---|
| Восстановление состояния клиента, поиск расхождений, извлечение фактов с цитатами | LLM |
| Наличие обязательных полей карточки (бюджет, район, тип объекта) | Прямая проверка CRM |
| «Тип контакта = агент» на этапе «Агент» | Прямая проверка CRM |
| Наличие ID Афины на «Закрытой продаже» | Прямая проверка CRM (уже есть в аудите) |
| Итоговый вердикт | Код по правилам |

## Три измерения

| Измерение | Что отвечает | Откуда |
|---|---|---|
| **Полнота** | все ли обязательные для этапа факты есть | LLM `signals` + поля карточки |
| **Достоверность** | комментарий брокера сходится с записью разговора | сверка LLM с двумя цитатами |
| **Подтверждённость** | факты только со слов брокера или есть опора на разговор | источник цитат |

## Вердикт

| Вердикт | Условие |
|---|---|
| 🟢 **Хорошо** | все обязательные факты есть, комментарий похож на разговор, ключевые поля карточки заполнены |
| 🟡 **Терпимо** | комментарий брокера в целом соответствует разговору, основные поля квалификации заполнены, но чего-то из полного набора не хватает |
| 🔴 **Плохо** | нечего восстановить, **или** есть существенное расхождение, **или** пустая карточка на этапе, где уже должна быть работа |
| ⚪ **Рано судить** | карточка на этапе меньше отсрочки |

**«Сверка невозможна»** — отдельный флаг, не влияющий на вердикт: если
расшифровок нет, достоверность не проверялась.

## Расхождения: мелкое vs существенное

**Мелкое** — не влияет на вердикт, но упоминается в отчёте:
* даты сдвинулись (в карточке одно, в разговоре другое)
* суммы близки (расхождение до 30 % LLM возвращает как `low`)
* уточнения формулировок

**Существенное** — сразу вердикт «плохо»:
* искажена позиция клиента (готов / думает / отказался)
* искажена готовность к сделке (выходим на задаток / берём паузу)
* цифры расходятся более чем на **30 %**
* контрагент назван неверно (клиент / продавец / агент)

Решение принимается кодом по полю `severity` расхождения, которое отдаёт LLM
(low / medium / high) — low — мелкое, medium/high — существенное.

## Что это потребует от кода

**Расширение схемы `signals`** — часть фактов агент уже извлекает (бюджет,
сроки, цена, следующий шаг), но добавятся:
* Покупатели: тип объекта, район, показанные объекты, реакция на показ,
  условия офера, причина откладывания / проигрыша.
* Продавцы: адрес и тип объекта, цена выставления, фотосессия,
  готовность документов.

**Прямые проверки CRM** — новый модуль без LLM:
* поля карточки на «Подборе» — **UF-коды получены и подключены**
  (`UF_CRM_1774363333518` бюджет · `UF_CRM_1774364869184` район · `UF_CRM_1747291787883` тип);
* `TYPE_ID = "AGENT"` в контактах карточки на этапе «Агент».

**Разбор `severity`** уже приходит от LLM в `contradictions`, надо только
использовать его для итогового вердикта.

**Отсрочка 3 дня на «Подборе»** — считается по `stage_entered_at`,
это поле уже вычисляется в основном аудите.
