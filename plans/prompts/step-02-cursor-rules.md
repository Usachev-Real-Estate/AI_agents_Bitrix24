# Промпт для Cursor — Создание `.cursor/rules`

> Скопируйте содержимое ниже и отправьте в Cursor (Agent mode, Codebase-aware).

---

Создай файл `.cursor/rules` в корне проекта. Это свод правил для AI-ассистента проекта `b24-ai-auditor` (Python, LangGraph, RouterAI → DeepSeek, fastbitrix24). Файл должен быть в формате markdown (UTF-8) и содержать ровно следующие секции:

## 1. Python Code Style

- Строго следуй PEP8. Используй flake8 с `max-line-length = 100`.
- Все функции и методы обязаны иметь type hints (аргументы и возвращаемое значение).
- Все публичные функции и классы обязаны иметь docstring в Google style.
- Именование: `snake_case` для функций, методов, переменных; `PascalCase` для классов; `UPPER_CASE` для констант.
- Используй `async/await` для всех операций ввода-вывода (сетевые запросы, вызовы LLM).
- Никаких `print()` в продакшен-коде — только `logging`.
- Импорты: стандартная библиотека → сторонние пакеты → локальные модули, каждая группа отделяется пустой строкой.

## 2. Project Structure

- Корень проекта: `b24-ai-auditor/`
- Весь код приложения лежит в `src/`
- Тесты лежат в `tests/`, зеркально повторяя структуру `src/`
- Конфигурация загружается через `pydantic-settings` (`BaseSettings`) из файла `.env`
- Системные промпты для LLM хранятся в `src/prompts.py` как константы
- Инструменты (обёртки над REST API Битрикс24) лежат в `src/tools.py`
- LangGraph граф и узлы агентов лежат в `src/graph.py`
- Точка входа: `src/main.py`
- Зависимости: `requirements.txt` (production) + `requirements-dev.txt` (линтеры/тесты)
- Управление пакетом: `setup.py` (setuptools, не poetry/pyproject.toml)

## 3. LangGraph & Agents Conventions

- Каждый узел графа (node) — отдельная `async` функция, принимающая и возвращающая состояние.
- Состояние графа описывается как `TypedDict` под названием `CRMState`.
- Инструменты (tools) — синхронные функции, оборачиваемые в декоратор `@tool` из `langchain_core.tools`.
- Все вызовы LLM выполняются через `ChatOpenAI` с compatible API.
- **LLM Proxy:** Используется RouterAI (`https://routerai.ru/api/v1`) как шлюз к DeepSeek.
- Модель `deepseek/deepseek-reasoner` (R1) используется ТОЛЬКО для узла Analyst (анализ нарушений).
- Модель `deepseek/deepseek-chat` (V3) используется для узлов Auditor (сбор данных) и Dispatcher (принятие мер).
- Системные промпты должны быть на русском языке и содержать жёсткие инструкции со ссылками на конкретные правила регламента.
- Все результаты работы LLM должны проходить валидацию перед использованием в инструментах действий.
- **Конфиденциальность:** чувствительные поля из CRM (паспортные данные, номера счетов) должны очищаться в инструментах до отправки в LLM.

## 4. Commit Message Format (Conventional Commits)

- `feat:` — новая функциональность (пример: `feat: add get_deal_context tool with timeline comments`)
- `fix:` — исправление ошибки (пример: `fix: handle empty timeline in deal context`)
- `refactor:` — рефакторинг без изменения функциональности
- `docs:` — изменения документации
- `test:` — добавление или изменение тестов
- `chore:` — рутинные задачи (зависимости, конфигурация, CI)
- Тело коммита (если есть) отделяется пустой строкой от заголовка
- Язык коммитов: русский или английский, но единообразно в проекте

## 5. Branch Naming

- `main` — production-ready код, только через merge request
- `develop` — основная ветка разработки
- `feature/<краткое-описание>` — новые фичи (пример: `feature/deal-auditor-node`)
- `fix/<краткое-описание>` — исправления (пример: `fix/timeout-b24-api`)
- `release/<версия>` — подготовка релиза (пример: `release/0.1.0`)
- Используй kebab-case в названиях веток

## 6. Tools & API Rules

- Все вызовы Битрикс24 REST API идут через библиотеку `fastbitrix24`.
- Каждый инструмент должен иметь таймаут (не более 30 секунд на запрос).
- Ошибки API должны логироваться и пробрасываться наверх как кастомные исключения.
- Инструменты НЕ должны вызывать методы-мутаторы (tasks.task.add, im.notify) если `DRY_RUN=true`.
- Все чувствительные данные (API ключи, webhook URL) читаются ТОЛЬКО из переменных окружения, никогда не хардкодятся.

## 7. Environment & OS

- Проект разрабатывается под Windows (локально) и Linux (Docker/Proxmox).
- Пути в Makefile: `venv\Scripts\...` для Windows, `venv/bin/...` для Linux.
- Переменные окружения в Windows cmd: `set VAR=value && command`.
- Кодировка всех файлов: UTF-8.
- Переносы строк: LF для `.py`, CRLF для `.bat`/`.cmd`.
